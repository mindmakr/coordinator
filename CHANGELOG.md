# Changelog

## 1.0.0 (2026-11-07)

Release notes for 1.0 (#14). Follow and steer a run from a phone, while builders and critics still run only on your machine. The service is ready to self-host today; the hosted app at app.coordinator.mindmakr.com opens with 1.0.1 (#42).

### What's new

- **Follow runs on the web (#11).** The Coordinator GitHub App reads the `coordinator-state` branch your lead pushes at pit stops and shows each run, its units, maps and project map to the people who can read that repo, and nobody else. Each issue and PR a run works on gets one tracker comment, kept current, and an organisation board can follow the units. Hosted beta at [app.coordinator.mindmakr.com](https://app.coordinator.mindmakr.com), free during the beta; the homepage has "Install the GitHub App" and "Sign in".
- **Answer from anywhere (#12).** Answer the lead's questions and add notes on the web dashboard, or with `/coordinator answer q3 b` and `/coordinator note "…"` in an issue or PR comment. Each is one commit on `coordinator-state`, only from people with push access. `run.mjs pull` takes them even after the lead's own later events, and `run.mjs watch --remote` brings them in within a minute, or at once when the service's doorbell rings. A change to a question the lead already used or decided never overrides it: it is kept as a flagged note.
- **Alerts (#12).** Web push, email (confirmed by a link first) and GitHub mentions when a run needs you, a unit stops, a run finishes, a PR merges, checks go red, a security alert lands or a lead goes quiet. Per-person quiet hours, digests and collapsing; a question's text only if you opt in.
- **Maps you can read (#20, #33).** Every unit box shows a status mark, its id and title; hover, focus or tap for its status, scores, time, last gap, links and files, with what it connects to lit. Maps keep their size on a phone and scroll in their box.
- **OpenAI Codex CLI** is the second supported harness: install path, an `AGENTS.md` block and an adapter note on what differs ([references/codex.md](skills/coordinator/references/codex.md)). `tools/codex-e2e.mjs` runs a small task end to end in `codex exec` and checks the run's own log. The first run used sub-agents and fixed the bug but stopped at the account's usage limit before a verdict; a run that closes `done` is still to come.
- **Self-host** the same service from one container and Postgres, with your own GitHub App from `service/app-manifest.json` (Docker and Dokploy).
- **Docs:** [install](docs/install.md), [connect](docs/connect.md), [self-host](docs/self-host.md), [permissions](docs/permissions.md) (each App permission and why, and what the doorbell does with your `gh` token) and [privacy](docs/privacy.md) (what the hosted service keeps and for how long, and what never leaves your machine).
- **Security hardening of the App and service** before the beta opens (#14), in four review rounds. Secret masking runs in linear time: long text is read in overlapping windows that stretch to whole tokens, so a secret across a window edge is still caught, and a quoted value is followed to its closing quote however long it is (tests count the characters read with `readCost`). One tenant cannot stall the others: logs are read in a small pool of worker threads, in turn per installation, with a reading-time budget each; repo syncs are queued (a few at once, at most two per installation, a burst of pushes to one repo becomes one sync), each stops after 5 minutes, and together they hold a bounded amount of log memory; tracker comments and board cards are refreshed in a lane of their own, after the sync, with a budget of GitHub calls per installation; uninstalling drops the installation's queued work. Webhooks are limited by where they come from: refused deliveries per address, 512 KB of bodies in flight per address group (IPv4 /24, IPv6 /64), a 10-second body deadline, and the last 6 MB of the budget kept for deliveries from GitHub's published hook addresses that name this App (anyone else's hooks from GitHub's addresses are capped per hook target); a delivery replayed under a new id is skipped by its body hash; `TRUSTED_PROXY_HOPS` finds the client behind a CDN. Alert email addresses are normalised (NFKC, IDNA) before they are confirmed or stored, and the confirmation limit counts `ann+1@` and `ann+2@` (and Gmail's dotted spellings) as one mailbox. Uninstalling deletes the installation's alerts, follows and audit rows too, and its id is kept so a late event cannot bring it back; removing a repo deletes its alerts. Details in `service/CHANGELOG.md`.

### Upgrading from 0.x

- Old runs load as they are. `migration.test.mjs` checks run folders written by the 0.1 to 0.5 releases' own scripts (`test/fixtures/old-runs`, made by `tools/make-old-runs.mjs`): each lists, shows, renders its dashboard and unit pages, takes a write that imports it into the event log, and goes through `push` and `pull`. `COORDINATOR_MIGRATION_SOURCES` adds real state folders (copied first; the test fails if a source changes). Checked on copies of 12 real runs from three state folders on the author's machine (7 from one product, 2 from a skills repository, 3 from this repository's own runs), 5 of them written before the event log existed.
- A self-hosted App registered before this release needs Contents raised to write, the three security-alert permissions and the `issue_comment` and alert events added, then the new permissions accepted on each installation ([permissions](docs/permissions.md)).
- **Licences:** the skill, scripts and shared code stay MIT; the service in `service/` is AGPL-3.0.

### Details

- **Secret masking is linear (c14, security review):** `lib/secrets.mjs` read `'token_'` x 2000 for 173 s because its named-value regex backtracked; it now reads long text in overlapping windows that stretch to whole tokens and follow a quoted value to its closing quote, with a small tokenizer for "<name> = <value>" and "<name> is <value>", and bounded repeats elsewhere. It catches the same secrets (a differential test against the old masker over 200,000 random inputs found no difference); adversarial inputs mask in milliseconds. Every string in an event is now at most 64 KiB (`MAX_TEXT` in `lib/eventschema.mjs`); `run.mjs` writes nothing near that, so existing logs load as before. Service fixes in `service/CHANGELOG.md`.

- **Service fixes:** "could not start" logs the real cause of a failed start, including each part of an `AggregateError` such as a refused database connection; the self-host guide runs as written (Docker Compose from a fresh clone to `/healthz` and the eight migrations), and repos installed before the service are synced by installation id.
- **Forced syncs finish:** `npm run sync -- <id> --force` on a repo with more logs than `SYNC_MAX_MB` is recorded in the database (`repos.reread`, migration 008) and carried on by every later sync until it is done, instead of re-reading the same first logs every time. The CLI stores an installation only after GitHub issues it a token, and never one that was uninstalled.
- **`tools/codex-e2e.mjs`** finds `codex.cmd` on Windows when there is no `codex.exe`, and sends the prompt on stdin.
- **"Answer changed after the lead decided":** an answer changed away after the lead closed the question by a decision is recorded as "answer changed after the lead decided: qN → …" instead of "answer changed after use" (`lib/incoming.mjs`), and the service's alert for it says the same (`answer-changed-decided`); both tested. `durability.md` says a closed local run still takes replayed answers and notes, and how to repair a forged event on the state branch that stops `pull` and `push`.
- **`/coordinator:doctor`** (`scripts/doctor.mjs`, `lib/doctor.mjs`): checks the setup and prints one line per item with ok, warn, FAIL or skip and a one-line fix: node, version (against the latest release tag), gh (login, repo and project scopes), git, context (`COORDINATOR.md` and its commands), state-dir, settings, state (a public `stateRepo` fails), locks, dashboards, artifacts, worktrees (linked `node_modules`), lessons, codex. `--json`, `--offline`; exit 1 on a failure; never prints a token. `serve` records its pid and port in `runs/<run>/serve.json` while it runs, so doctor can tell a live dashboard from a stale one.
- **Setup questions in `/coordinator:init`:** one batch for where run state goes, the theme, default budgets, the merge rule and the hosted app, written to `.coordinator/coordinator.json` (`lib/settings.mjs`; new optional keys `state`, `theme`, `budgets`, `merge`, `models`) and `COORDINATOR.md`, then doctor. A re-run shows the current values and changes only what the person changes. `state: "local"` refuses a branch push; `budgets` become `run.mjs init`'s defaults; `theme` is the dashboard's fallback theme.
- **`run.mjs adopt <run> [--dry-run]`:** copies files a run mentions by path (screenshots, PDFs, logs, md and json reports in worktrees or scratch folders) into the run folder as evidence of the unit that names them, so deleting a worktree loses nothing. Idempotent; capped per file and per run; refuses `node_modules`, `.git`, secret-looking names and symbolic links. Evidence files now carry a sha256 that doctor verifies, and `--file` takes pdf, md and json too. `close` warns while mentioned files are unadopted; a stored file that went missing shows as "missing" on the dashboard instead of a broken image. Briefs tell builders and critics to attach what they make with `--file`. Adopt copies only from the project, its worktrees, the OS temp folder and the state folder, never from home configuration (`~/.claude*`, `~/.ssh`, `AppData/Roaming`, …); reads quoted paths and paths with spaces or brackets, marking uncertain ones `unclear`; re-copies a damaged stored copy from its source (`repaired`). An adopted PDF has the new evidence kind `pdf`. Doctor's fix for a damaged artifact names its source or the evidence step; a stale `serve.json` is removed; `models.strong` is accepted and a judge below it warns. Prose starting with / is not taken for a path; a root holding the home folder and hard links outside the project are refused; older adopted PDFs are re-tagged pdf.

- **Model routing, on by default:** mechanical builder work (docs, copy, translations, renames, fixtures, mirror changes) goes to a cheaper model; critics, specialists, the integrator and builders on security, money, migrations or auth never go below `strong` (default `opus`, configurable for Codex), whatever the table says; full ids (`claude-sonnet-4-5`) count as their family, and a unit in several classes gets the strongest choice (`references/routing.md`, `lib/models.mjs`). Off or a custom table through `"models"` in `.coordinator/coordinator.json` (`false`, or e.g. `{"critic":"opus","builder":"opus","mechanical":"sonnet"}`), `run.mjs init --models on|off`, and a question in `/coordinator:init`. `run.mjs models [--role R --class C]` prints the table or one choice. `start --model M --why W` and `verdict --model M` record who built and judged each round (a judge below `strong`, or an unranked name other than it, is refused while routing is on; `integrate --model` too). After any cheap fail since the last strong build, `next` suggests `strong` and `start` needs `--model` at or above it, or a cheaper one with `--force-model "reason"`. A `strong` (and a judge or escalation model) that mentions Claude in any spelling must parse to opus, after Bedrock and Vertex wrappers are stripped; family ids parse strictly; pinned classes match by word and word stem (migrate, payroll, salary, ledger, refund, wallet, fee, disburse, KYC, session, CSRF, RBAC, role, IBAN, schema, payments, billing, invoicing, authentication, authorization, permissions, secrets, crypto, PII, personal data); `stats` and `show` group models by family; with routing on, a missing `--model` is recorded as `unspecified` and the dashboard counts those rounds. The dashboard's budget block shows pass rate per builder model; the unit card and page say "built by sonnet (docs-only) · judged by opus", and `stats` adds rounds and pass rate per builder model. Old state loads: the fields are optional.
- **Walk the Flow and Goal relevance maps, and export any page as PDF:** hovering a box lights it and its direct children only; hovering a line lights its two ends: lines are focusable, their pointer targets sit under every box in a wide and a narrow layer, and lines from one box start apart, so each line and box gets the pointer it is under (`test/browser/hits.check.mjs` checks it on real runs). On the live page a click, tap, Enter or Space selects a box (again, Escape or Clear to unselect) with a floating panel (the map never moves) with a breadcrumb, an **Open unit** button, a children list, arrow keys to walk one level at a time, a context menu (right-click, long-press, Menu key: open, new tab, select children, copy link), **Find** and **Focus**, plus counts per map. Flow's line ends now each mean one thing and the legend draws them: filled arrowhead to the unit waited for, a ring at a linked issue or PR, an open arrowhead to a follow-up. Selection, Find, Focus, a pinned panel and map scroll survive a reload and a live update (selection in the URL hash). Every page gets **Export PDF** (the browser's print; the snapshot says Ctrl+P) with print styles: light theme, toggles open, live controls hidden, maps fitted to the page, nothing cut across pages where it fits, title and page numbers. `references/hud.md`.
- **Review round 2 (#12):** an answer changed on the web after the lead used the question no longer wedges `pull` and `push`: the lead keeps the used answer and the change is recorded as a person's note flagged `changedAfterUse` ("answer changed after use", design 9). A branch answer or note with fields `run.mjs` never writes is refused instead of being re-added on every pull. AGENTS.md names `lib/doorbell.mjs` as the other network caller (a test keeps the list honest).
- **`pull` takes answers after the lead's own later events** (#12): a lead that logged beats or verdicts after its push no longer stops with "different histories" when an answer or note arrives on the `coordinator-state` branch. `pull` replays the copy's extra `answer` and person `note` events on the local log, in order, renumbered, through the same checks and lock as `run.mjs answer` and `note` (`lib/incoming.mjs`); anything else is still refused, and a second pull adds nothing. The next `push` replaces the copy's log with the local one, which holds them; a push while the copy has answers or notes not yet replayed is refused ("pull first"). `references/durability.md`.
- **Answers and notes from anywhere** (#12, first half): the web dashboard takes answers and notes, committed to the run's event log on the `coordinator-state` branch with the person's own token, only from people with push access (readers see the forms disabled, with the reason); `/coordinator answer qN <option>` / `"text"` and `/coordinator note <text>` work in issue and PR comments. Both write the same `answer` / `note` event `run.mjs` does, so the lead's `pull` fast-forwards onto it. The dashboard's forms take a `ctx.form` (token field name, path prefix, disabled reason) so a hosted copy can carry them without the live script. Details in `service/CHANGELOG.md`.
- **Plugin icon:** `.claude-plugin/icon.png` (512 px, the dashboard's mark), so `claude plugin validate` no longer warns ICON_MISSING.
- **Service follow-ups from the c11 review:** owed trail writes survive a crash, trail sequence values never repeat, and a stale same-named repo row cannot hide a page. Details in `service/CHANGELOG.md`.
- **`watch --remote`** (#12): `run.mjs watch <run> --remote [--every 10-60]` also pulls the run from its state branch every 30 s, so answers and notes made away from this machine arrive within a minute, and at once when the coordinator service's doorbell rings (`COORDINATOR_SERVICE` or `"service"` in `.coordinator/coordinator.json`; the person's `gh` login mints a short-lived doorbell token). Node built-ins only (`lib/doorbell.mjs`, `lib/remote.mjs`).
- **Service: alerts and the doorbell** (#12): web push, email and GitHub mentions for every alert trigger, with per-person quiet hours, digests, collapse and minimal content; an SSE doorbell that carries only "run X changed". Details in `service/CHANGELOG.md`.
- **Map labels and stats panels:** every unit box on the maps carries a status mark (✓ ✗ ■ ○ ▶ ◆, never colour alone), its id and a clipped title; hovering, focusing or tapping a box shows its status, round, scores, time spent, last gap, linked issues and PRs and files touched, and lights what it connects to while the rest dims. Escape or a tap elsewhere closes it. The project map does the same for modules (files and helpers). CSS-driven, so the snapshot works with no script; the view model gains `files` (from the last gaming check). The project map's graph is a group, not an image, so its links reach assistive technology.
- **Maps stay readable on a phone:** maps draw at their own size (ids 13 px, the smallest text 10.5 px) and scroll inside their box with a hint, instead of shrinking; the mind map opens centred. Stacked edges say "waits on" and point to the unit waited for; issue and PR boxes say which units link them; follow-ups say which unit filed them; goal behaviours say which units serve them. The panel is a non-modal dialog: Tab from a box enters it, Tab past its last link moves on, Escape returns to the box; it stays open while the pointer is on it and is placed clear of the boxes it lights. Another run's pages name that run in the header. Hovering a unit keeps the units it waits on, the ones waiting on it and (in the mind map) those sharing an issue or PR lit; dimming stays while focus is in a panel; keyboard focus moves panels at once (the grace delay is for the pointer only); a large mind map opens on its first unit.

Nothing studied changes the fence or the bar (`references/learning.md`).
- **Lessons with sources:** `lessons.mjs add --source URL` (repeatable, merged on a repeat); `list` shows `from` and `sources`. Tags stay free (`security`, `design`, …).

- Older state and lesson files load: `studies`, `budget.maxStudies` and `sources` are optional.
- **The event log is the run:** every change appends one JSON line to `runs/<run>/events.jsonl` (`v`, `seq`, `at`, `kind`, `unit`, and the change as `set`/`del`/`push` ops), under the run's lock, atomically. Ops name records in lists by id (`["units", {"id": "u1"}, "status"]`), so each event reads on its own; `unit.add` carries the whole unit. `state.json` is now a compact snapshot derived from it: keys sorted, units in planned order, and a `snapshot` block with the last `seq`, a SHA-256 of the log up to it, and a SHA-256 of the state. A reader that finds the log ahead of the snapshot or a hash that does not match rebuilds from the events; a torn line, bad JSON, a schema break or a `seq` gap fails loudly. Each event kind has a JSON Schema, checked on write and on read. Format in `references/durability.md`.
- **Old runs load:** a `state.json` with no event log loads as before; its first change writes a `run.imported` baseline. A `state.json` changed outside `run.mjs` is kept, as a `state.edited` event.
- **State in the repo at pit stops:** `run.mjs push <run> [--to branch|./folder]` writes the run's events, snapshot and README, project lessons and a stats line per closed run, masked (secrets, the project path, the home folder), to an orphan `coordinator-state` branch, with a normal push (hooks run). It only moves the copy forward: a copy with events this machine lacks, or a different history, is refused. Never to `main` or the default branch, never to a branch that holds no coordinator state, never to a public repo unless `.coordinator/coordinator.json` names a private companion repo (`stateRepo`). `run.mjs pull <run> [--from …]` restores the run on another machine or appends newer events; it never overwrites local events the copy lacks. The run playbook pushes after a merge, a decision and the close.
- **Project map** (#21): `run.mjs map <run> [--root dir] [--max-seconds 60] [--unit U] [--fresh] [--force]` maps the code with Node built-ins only: modules and imports (relative, tsconfig `paths`/`baseUrl` with relative `extends`, workspace packages by `exports`, CommonJS, dynamic imports), shared helpers with who uses them (through re-exports), env vars and settings keys with where they are read and written, routes (Fastify/Express with `register`/`use` prefixes, Next.js route handlers) with the services their handler actually calls (one local call deep), screens (Next.js app and pages routers, Expo Router) with the routes their client calls reach, message keys used in code or missing a locale, and reuse candidates (function bodies of the same shape). Other languages get an import scan. Read-only and capped in time; a build cut short is refused over a complete map unless `--force`. A broken log is named with `--fresh` as the way out, on the CLI and on `/map`.
- **Map storage:** `map/events.jsonl` (append-only `map.build`, `map.delta`, `map.done`, with `v`, `seq`, `at`, `kind`, optional `unit`), `map/map.json` (snapshot with sorted keys and records, one record per line, `upTo` seq and SHA-256) and `map/map.md`. Schemas checked on write and read; a stale or tampered snapshot is replayed from the events; a gap, a bad line or a replay that misses the digest fails loudly.
- **Pit stops:** `map <run> --pit-stop` stages `events.jsonl` and `map.md` in the run's own `pit-stop/map/` (never the project's tree; `map.json` is rebuilt from the log). `run.mjs push` carries them to the `coordinator-state` branch with the run (masked, refused when the branch has map events the stage lacks) and `pull` restores or fast-forwards them, keeping a local map that is ahead or differs. Map strings are masked when recorded; the map has its own files and lock, apart from the run's log. `--dest dir` copies them to a named folder instead.
- **Map view:** `map.html` beside the snapshot, `/map` and `/run/<run>/map` on the live dashboard, linked from the run's header: a layered import graph in inline SVG with CSS-only filters (areas, link weight, tests, cycles), hover to light a box's links, boxes and rows linking to GitHub; then routes, screens, settings, helpers and reuse candidates.
- **Briefs:** `run.mjs touches <run> <path> [--json]` prints what a file imports, who reaches it, the helpers and settings involved, its surfaces (direct first, then the nearest that reach it, with the total) and its reuse candidates; the builder brief includes it when the run has a map.
- **Map: a sanctioned reset and scoped handlers:** `map <run> --reset-stage` starts a new map history (a `map.reset` line naming the SHA-256 of the history it replaces) that `push` and `pull` accept; a route's services resolve the names its handler uses by scope, so handlers sharing a variable name no longer borrow each other's services; `/run/<other>/map` (and its error page) shows that run's nav; a forced partial build keeps the complete build's message figures.

## 0.5.0 (2026-11-06)

A live dashboard, and a bar made of behaviours with evidence attached. From the owner's feedback on the 0.4 HUD.

- **Live dashboard:** `run.mjs serve` pushes changes over Server-Sent Events (same token, 127.0.0.1 only, 15 s heartbeat, reconnect with backoff) and the page swaps only the blocks that changed, never one being typed in. A **Live** dot shows connected or reconnecting. No more full-page reloads.
- **Kept state:** open sections, scroll position, theme and timeline filters are remembered per browser, across live updates and reloads.
- **Theme toggle:** System, Light or Dark.
- **Behaviours make up the bar:** `add --behaviour "Given … when … then …"` (repeatable) or `behave <run> <unit> [--id B1] --text …` / `--id B1 --remove`; `behaviours <run>` lists them. The critic marks each with `verdict … --behaviour B1=pass:"evidence"`; `verdict pass` is refused while any behaviour is failing or unchecked, and `start` sets them back to unchecked.
- **Evidence per unit and behaviour:** `evidence <run> <unit> [--behaviour B1] (--text | --file | --url) --kind test|screenshot|log|link [--label]`. Text is masked and capped; images and small logs are checked and copied into `artifacts/<unit>/`; URLs must be http(s). Test output shows in a monospace block, collapsed when long; screenshots as thumbnails that open full size.
- **Goal evidence:** `behave <run> --goal …`, `evidence <run> --goal …`; the dashboard opens with **Goal: met / not yet**, and `integrate pass` needs every goal behaviour passing.
- **A page per unit** (`/unit/<id>`, live; `units/<id>.html` in the snapshot): behaviours, evidence, every round with the builder's report (`built --report`), the critic's verdict, score, cause and behaviour marks, notes and questions, links, and **the unit's own timeline** (start, beats with `beat --text`, built, verdicts, strategy, evidence, questions, answers, notes, links, merge, stop).
- **Timelines:** colour-coded badges with text labels, search, kind and unit filters, time ranges (30 min to 8+ days) and sort, all kept per browser.
- **Links everywhere:** URLs, `owner/repo#n`, and against the run's repo (`init --repo`, else the project's GitHub remote) `#n`, commit shas and branch names, each opening in a new tab with no referrer. `add`/`link --issue … --pr …` (repeatable, for linked repos) and `link --merge …` put chips on the card and the unit page.
- **Looks like the project:** `init --theme file.css` or `Theme:` in `COORDINATOR.md` maps the design system's custom properties (shadcn, Tailwind 4 `@theme`, daisyUI) onto the dashboard; unsafe values are dropped and nothing is loaded.
- **Retrying / Quiet, not "needs attention":** the unit badge says the lead is handling it (failed twice in a row; agent silent), with the reason on hover and a legend. Only Needs you and question cards address the person.
- **Local times:** the live pages show times in the viewer's locale and zone (relative within 24 h, full local time on hover); the snapshot keeps ISO with UTC spelled out. Every time is a `<time datetime>`.
- **Brand:** "Coordinator by mindmakr" mark, favicon, page titles ("<run> · Coordinator by mindmakr") and footer with the version.
- **Your place is kept:** live updates change the page in place (keyed rows, cards and sections, every key unique on its page; kept nodes stay), so the browser's own scroll anchoring holds the reader's place. A reload restores the scroll position once images and fonts have loaded. Known issue: in Chromium, an append to a list just above the top of the screen inside a tall card can shift the view (`references/hud.md`). Event keys carry a hash of the text and a number, so two events never share one.
- **Status at a glance:** a connection pill (Live, Reconnecting, Disconnected, Finished; after a server restart it says to open the new link and stops retrying, with a Retry button), a status dot per unit, active units first and finished ones dimmed (with Show finished), no pulsing under reduced motion.
- **Self-explaining numbers:** "Tries used: 2 of 4", "Score per try (0–10)" with a tooltip per dot (try, result, score, cause), one try as words, budget cards that explain themselves; only limits that block work turn red.
- **Search highlights:** every match in the visible timeline rows is marked (case, accent and diacritic insensitive, text nodes only), with an "n matches" count; kept across live updates.
- **Answered questions leave the open list:** the Questions card counts open ones only; answered and decided ones move to a collapsed Answered group that leads with the answer.
- **Bar changes are on the record:** after freeze, removing or rewording a behaviour needs `--reason` (logged as a bar note), and none changes while its unit is being judged. Behaviours set at `add` show on the timeline under their own kind.
- With no `--repo` and no GitHub remote, `#n` resolves against the GitHub links already in the run.
- **Snapshot:** `hud.html` is now a static read-only snapshot (no meta refresh, so open sections stay open); one page per unit beside it; small screenshots embedded.
- Older state files load: every new field is optional.

## 0.4.0 (2026-11-06)

The person answers the lead's questions and adds notes from the HUD, and the lead hears about it at once.

- **Questions shaped like the question tool:** `run.mjs ask <run> --question Q --header H --option "label|description" …` (2–4 options, the recommended one first, free text always allowed, `--multi`, `--unit`). The older `note --kind question` still works and shows as a question with no options.
- **Answers you can change until used:** `run.mjs answer <run> qN --choice … --other … --by person|lead` records an answer; `use-answer` marks it acted on, after which it is refused. Every answer is kept in the question's history. `run.mjs questions <run>` lists them all.
- **Notes from the person:** `note --kind person --text T [--unit U]`, shown on the unit card and in "Notes from you".
- **The answer page:** `run.mjs serve <run> [--port P]` serves the HUD with answer forms and note boxes on 127.0.0.1 only, behind a token made at each start; a POST also needs the page's own origin. Writes use the same locked state code as the CLI. It reloads like the file but never while a form is being filled in (one inline script, allowed by a per-response nonce). `hud.html` on disk stays script-free and read-only, and says how to get the answer page.
- **The lead hears at once:** `run.mjs watch <run>` prints one line per new or changed answer and per note, polling every 2 s; the lead runs it in the background so an answer wakes it (`references/commands/run.md`).
- Older state files load: questions without options or history read as before.

## 0.3.0 (2026-11-06)

The HUD explains the run in plain words (#7).

- **Situation, Needs you, Time left** at the top of `hud.html` and `run.mjs show`: the lead's latest `note --kind situation` (or a count of tasks in progress, done and waiting), a highlighted box of open questions with the lead's recommendation (`note --kind question --recommend R`, closed by `note --kind decision --answers qN`), and a rough time left from the median try so far and the time budget.
- **One plain sentence per unit**, before the scores: what it is for, how it went, what happens next. `add` takes `--title` and an http(s) `--link`. Raw gap and evidence move behind a toggle.
- **Needs attention** badge on a unit that failed two tries in a row or whose agent went quiet.
- The lead writes a situation note after each verdict and each merge (`references/commands/run.md`).
- All new fields are optional: older state files load and render as before.

## 0.2.0 (2026-11-06)

From the first real run and its owner's feedback.

- **HUD** (#3):
  - `run.mjs show` prints a compact text view: units, phase, rounds, score trend, budget used against its limits (time included), the next step, and counts of questions, follow-ups and decisions;
  - every change rewrites `hud.html` beside the state, in the same lock: one fixed, self-contained template with the unit board, score charts, budget bars, a timeline, and the decisions, questions and follow-ups. No scripts, no network, escaped state text, reloads every 15 s while the run is open, light and dark, phone width;
  - `run.mjs hud <run>` rewrites it on demand and prints its path. `references/hud.md` covers publishing it as an Artifact in Claude Code.
- **Same gap by root cause** (#5): the critic replies with a `CAUSE:` tag, `verdict` and `integrate` take `--cause`, and two rounds with the same cause count as the same gap even when worded differently. Without a cause on both rounds the wording decides, so older state files still load and behave as before.
- **Questions through the question tool** (#2): intake and gated-action questions go through the harness's question tool (AskUserQuestion in Claude Code), each with a short context line and the recommendation first, or a numbered list where there is no such tool. Builders, critics and integrators never ask the person.
- **Short replies** (#1): outcome first, as short as the content allows, with a context line when several pieces of work are active.

## 0.1.0 (2026-11-06)

First public version.

- Commands: `init`, `run`, `status`, `retro`.
- One intake batch, then an unattended loop: builders, blind critics, an integrator.
- Stop rules in code:
  - round and time budgets;
  - no progress;
  - the same gap after a change of strategy;
  - a blocked stacked unit;
  - a cap on scope added after the split;
  - out-of-order steps refused.
- `detect.mjs`: flags focused, skipped, deleted or renamed-away tests, removed or trivialised assertions, rewritten snapshots, suppressed checks, ignored failures, and edits outside the fence.
- Durable state:
  - atomic and locked;
  - shared across git worktrees;
  - heartbeats for builders and critics;
  - resume after a crash or compaction.
- Lessons: merged, ranked and pruned. Budgets tuned from past runs. Improvements contributed upstream with the user's approval.
- Craft bar (no slop). UI built from researched or supplied references. Roles staffed from the harness's own agents.
