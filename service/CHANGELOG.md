# Changelog: Coordinator service

## Unreleased

- **Security review fixes (round 3):** the webhook signature is always checked first and a verified delivery is never rate limited (refused deliveries from GitHub's shared addresses could block real ones); a periodic resync of every installation (`RESYNC_MINUTES`, default 15) heals missed deliveries. The tracker template checks every number (`maxRounds`, scores) and drops anything but id characters from the marker. The consent check is cached for at most 60 s; runs over 50 units are refused, at most 10 links per unit are written, and comment writes are capped per installation.
- **Security review fixes (round 2):** tracker comments and board writes are fenced to the run's project (the state repo, plus linked repos listed in `coordinator.json` `repos` whose own default branch names the state repo as `primary`); links outside it are read-only. Run text in tracker comments is in code spans (no autolinks, mentions or markup). Deeply nested lessons, `coordinator.json` or state no longer crash a sync; the repo records why. `ACCESS_TTL_SECONDS` capped at 60; PKCE and a fresh session on every sign-in; signed webhooks are never rate limited; unknown repos get the same GitHub check as unreadable ones. The HTTP, access and webhook tests run against Postgres too (a throwaway schema per app) when `TEST_DATABASE_URL` is set.
- **The GitHub trail (#11):** one tracker comment per unit on each linked issue or PR (the skill's `lib/tracker.mjs` template), edited in place, never re-sent unchanged, re-made when deleted, and status only outside the run's own private repo; board fields Run and Unit state (and the board's Status, when mapped) on an organisation board named in `coordinator.json`; `pull_request` and `check_suite` webhooks stored against the PR, shown in run and unit timelines to viewers who can read that repo, and refreshing the trail. Tokens narrowed per job; App permissions: issues and pull requests write, checks read, organisation projects write; contents stays read.
- **Project map** on the web (`/run/<run>/map`), from the pushed `runs/<run>/map/events.jsonl`, replayed and checked with the skill's `lib/map/log.mjs` (new `fromText`); linked from the header next to Maps; a bad log keeps the last good map.
- **Maps** on the web: `/r/<owner>/<repo>/run/<run>/maps`, from the skill's maps page. A `REPO_PAGES` hook for more repo pages (the project map).
- The Needs-you box says to answer in the chat for now; evidence files show as "file kept locally" instead of links.
- **First release (#11): GitHub App and read-only web dashboard.** Webhook ingest of the `coordinator-state` branch (signature checked, deliveries de-duplicated, unchanged tips and logs not read again, every log validated with the skill's event schema and masked again), a Postgres read model (in memory without `DATABASE_URL`), sign-in through the App's user authorisation, a per-request read-permission check with GitHub (cached per person for 60 s; no access is a 404), and the projects, runs, run, unit and coordinator pages drawn by the skill's own renderers. Manual sync from a repo page or `npm run sync`. Dockerfile, docker compose for local Postgres, App manifest and Dokploy notes in the README. AGPL-3.0.
